## Bug 1: Navigation Freezing & Broken Back Button
- **Issue:** The header back button (top right/left) does not work when navigating deep into a screen. Swiping left-to-right works. Furthermore, the `MainTabs` bottom navigation stops responding after 1-2 uses.
- **Expected Fix:** Check the React Navigation structure (prevent nested navigator conflicts). Ensure `navigation.goBack()` is correctly bound to the header button. Resolve any state mutation or unmount issues causing `MainTabs` to freeze.

## Bug 2: Missing Back Button in "Create Room" Screen
- **Issue:** When entering the "Create Room" (Multiplayer) screen, there is no back button to return to the previous screen.
- **Expected Fix:** Add a UI back button (e.g., `TouchableOpacity` with an Icon) or enable the default header back button via React Navigation `options={{ headerShown: true }}`.

## Bug 3: Incorrect Clipboard Data
- **Issue:** In the created room, pressing the "Copy" button copies the hardcoded text `"มาเล่น"` instead of the actual generated Room Code / PIN.
- **Expected Fix:** Update the `Clipboard.setStringAsync(...)` (from `expo-clipboard`) function to pass the dynamic `roomCode` variable instead of the static string.

## Bug 4: Multi-Select Categories (Single Player)
- **Issue:** The category filter currently only allows selecting one category at a time.
- **Expected Fix:** 
  1. Change the category state from a single string to an array (e.g., `const [selectedCategories, setSelectedCategories] = useState([])`).
  2. Allow toggling (add/remove) multiple categories (e.g., "อาหารไทย" AND "ญี่ปุ่น").
  3. Update the randomizer logic to pool items from ALL selected categories before picking a random item.

## Bug 5: "Add Custom Menu" Layout Issue
- **Issue:** When pressing "เพิ่มเมนูส่วนตัว" (Add Custom Menu) in the single-player screen, the input/component renders at the absolute top of the screen instead of the bottom.
- **Expected Fix:** Adjust the Flexbox layout. Wrap the custom menu component in a view with `justifyContent: 'flex-end'` or position it using absolute positioning at the bottom. If it's an input field, wrap it in a `KeyboardAvoidingView`.

## Bug 6: Guest Profile Picture Persistent Cache
- **Issue:** Guest users should not have a profile picture. The user previously added one, deleted it from the DB, but the image still appears.
- **Expected Fix:** 
  1. Enforce a strict conditional render: `if (isGuest) return <DefaultAvatar />`.
  2. To fix the caching issue for deleted images, suggest appending a timestamp to the image URI (`uri: imageUrl + '?t=' + new Date().getTime()`) or bypass the cached state entirely when the user is a Guest.
